# Layout A e B alternáveis — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar as direções A (mapa primeiro) e B (custos primeiro, com mapa vivo) sobre componentes compartilhados, com chave `VITE_LAYOUT` + troca em Ajustes sem recarregar, tokens claro/escuro e as decisões D2–D8.

**Architecture:** `AppShell` vira um seletor fino que renderiza o shell do layout ativo (registro `core/layout/layouts.ts`, shells `lazy`). Estado (mapStore/routeStore) e blocos de UI são compartilhados; cada shell só compõe. A prévia do traçado é um hook cancelável que publica em `mapStore.preview`.

**Tech Stack:** React 18, Vite, Tailwind (tokens HSL), zustand, MapLibre (stub nos testes), Radix (`accordion`, `switch`, `toggle-group`, `radio-group` — só os usados), vitest + jsdom, Playwright (só F11).

**Spec:** `docs/superpowers/specs/2026-11-22-layout-a-b-design.md`

## Global Constraints

- Todos os comandos via `agentop run --rm -- <cmd>`; nunca nas portas 47291/47292; sem túneis públicos.
- Cada fase = 1 PR pequena contra `main`, com testes TDD (vermelho → verde) e `pnpm --filter web typecheck && pnpm --filter web test && pnpm --filter web lint` verdes.
- **Estabilidade da suíte:** antes e depois da fase rodar `pnpm --filter web test` 3×, registrar duração e falhas no corpo da PR. Como a suíte já tem flakiness conhecido, a linha de base deve listar comando, duração e assinatura dos timeouts existentes; reprovar se aparecer assinatura nova, se uma falha conhecida aumentar de frequência ou se a mediana crescer > 10 %. Não chamar três verdes de pré-requisito quando a baseline já falha. Em cada commit, rodar primeiro os testes tocados; não editar `vitest.config.ts`.
- Testes novos: `{ timeout: 3000 }` em todo `findBy*`/`waitFor`; `vi.useFakeTimers()` para debounce/animação (restaurar em `afterEach`); ≤ 5 interações por `it`; sem render do app inteiro (exceto 1 teste de integração por shell, MapLibre stub); reset de `localStorage`, `useLayoutStore`, `useMapStore`, `useRouteStore` no `beforeEach`.
- Chaves/valores: `localStorage` `qualroteiro:layout` ∈ `'a'|'b'`; env `VITE_LAYOUT=a|b` (padrão `a`); env `VITE_LIVE_PREVIEW` (`"false"` desliga); debounce da prévia 700 ms; breakpoint mobile `< 768 px`; painel A 416 px; rail 76 px; alvos ≥ 44 px.
- Cores só por token; sem `#hex`/`hsl(`/`rgb(` literal em `core/map/**` (exceto `theme.ts`) nem classes `amber|emerald|red|green|blue-N`/`bg-white` em `src/**/*.tsx`.
- Texto da UI em pt-BR; nomes acessíveis existentes preservados (testes por nome); nenhum link/botão duplicado com o mesmo nome acessível no DOM.
- QA por modelo diferente do autor. Nada de segredo em código/PR (`vault://` se algo precisar de chave).
- Não mergear; PR só após verde.

## Review Focus

1. **Troca de layout no meio de uma consulta** (A→B→A com origem/destino/resultado): estado preservado, mapa **não** recriado (`Map` construído 1×). Teste em F2/F10.
2. **`localStorage` com valor inválido ou indisponível** (`'x'`, Safari privado lança): cai no padrão do build sem exceção. Teste em F2.
3. **Prévia com só 1 ponto, texto livre, ponto apagado, ou mudança rápida:** nenhuma chamada / chamada anterior abortada / prévia some; erro 422/rede silencioso. Teste em F9.
4. **Troca de tema com mapa montado:** pinos e traçado mudam sem recriar o mapa. Teste em F3.
5. **Resultado com dados vazios** ("Valor não disponível", 0 praças, 1 só alternativa): hero, tabela e rótulos não quebram. Testes em F5/F10.
